# Shared Forecast Validation

## Scope

Editable recurring income/costs, residual spending, dated goals, and structured
conversation-memory events now feed one monthly cash/wealth projection in Plan.
The advisor has a read-only tool for the same saved forecast. Tests use synthetic
financial records; no real statements, credentials, or paid AI calls are included.

## Cross-Widget Identity Map

| Surface | Source | Definition |
| --- | --- | --- |
| Spending | `/finance/transactions` | Selected-period actual credits/debits, excluding marked transfers |
| Recurring payments | `/engine/recurring/rules` | Per-payment source amount and frequency |
| Forecast assumptions | `/engine/forecast` | Same source rules; residual medians exclude their matched history |
| Forecast chart, three-month cash, goal outcomes, monthly rows | One forecast response | Same enabled assumptions and saved settings |
| Advisor forecast tool | `load_forecast` | Same service as REST, with no raw transaction payload |

Historical totals and forward estimates are deliberately distinct. The synthetic
fixture has stable monthly income/spending, so both totals can be checked exactly.

## Verified Numbers

Fixture: $20,000 cash, $10,000 investments, $5,000 monthly income, $1,000 rent,
$60 internet, $500 groceries, and a $6,000 December wedding. Zero investment
returns/contributions isolate cash-flow arithmetic.

- Recurring costs: $1,060; everyday spending: $500; total monthly spending: $1,560.
- November cash: $23,440; December: $20,880; January: $24,320.
- Twelve-month ending wealth: $65,280.
- Disable wedding: January cash rises by exactly $6,000, to $30,320.
- Then change groceries to $700: January cash becomes $29,720.
- Refresh/reload preserves the toggle and amount. Failed writes restore the saved
  state and show an error rather than claiming success.

Unit checks also cover debt-payment caps, savings reservations, no duplicate use
of cash, transfer neutrality, refunds, excluded partial months, annual/biweekly
cadence, fixed-seed reproducibility, matching horizon prefixes, percentile order,
authenticated endpoint validation, user scoping, and REST/MCP equality.

## Independent Review

The numerical reviewer found and the implementation corrected:

1. Goal/memory aliases could double-count a wedding, while distinct same-label
   plans could disappear. Stable note identities, explicit links and distinct
   event intent now govern consolidation.
2. Partial memory changes could erase known amounts. Updates preserve known
   fields and support explicit cancellation.
3. Debt outputs could claim funding for a larger target than the actual payoff.
   Outputs separate effective payment and requested target; the monthly UI shows
   the debt-payment column.
4. Missing spending history could appear as zero. The API and visible UI now flag
   missing everyday-spending/income estimates.
5. Resetting a promoted memory override could resurrect its old value. Migration
   consumes the alias and preserves reset through reload, including explicit
   goal links with different names.

Final reviewer verdict: no remaining blocking numerical issues within the defined
model. Independent probes passed 480 monthly cash identities and 40 net-worth
conservation checks. This is engineering validation, not financial-model calibration.

## Remaining Boundaries

Only investment returns are stochastic. Income/spending are fixed or scheduled;
cash-funding outcomes are therefore conditional on those assumptions. No taxes,
inflation, debt interest, automatic security sales, or property appreciation are
modeled. Remaining current-month activity is omitted, explicitly disclosed in UI.
Saved goals take precedence over linked memory; manual overrides take precedence
over both. See [the model documentation](../forecast.md) for reproduction commands.
